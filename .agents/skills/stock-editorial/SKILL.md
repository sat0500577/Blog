# 주식 블로그 기획·편집

프로젝트의 AGENTS.md를 따른다. 제목만 수정하는 요청에는 필요한 단계만 적용한다.

새 원고나 기획을 바꾸는 집필 요청마다 [Notion 기획 인계 절차](references/notion-planning-handoff.md)를 읽고 관련 회의록 본문을 실제 조회한다. 확정·제안·미정을 구분해 브리프에 반영하고, 최신 사용자 지시를 우선한다. 작가에게 조회 도구가 없으면 편집장이 본문과 출처를 전달한다. 이전 요약이나 검색 결과만으로 이번 조회를 대신하지 않는다.

1. 독자가 답을 얻어야 할 질문을 한 문장으로 쓴다.
2. 브리프에 주제, 대상 독자, 시장·종목, 기준일, 글 목적, 분량, 플랫폼을 적는다. 미정 항목을 사실처럼 채우지 않는다.
3. 반드시 확인할 주장 3~5개와 필요한 자료를 정한다.
4. 자료 확보 후 핵심 답변, 근거, 위험 요인, 관찰 지표 순으로 개요를 구성한다.
5. 최종 편집에서 제목과 본문 일치, 출처 연결, 사실과 전망 구분, 주요 검수 이슈 해결 여부를 확인한다.
6. 회의록의 금융 사실이 공식 자료로 재검증됐는지, 내부 회의 정보가 공개 본문에 노출되지 않았는지 확인한다. 참조 URL·회의일·조회일·반영 결정·미해결 사항은 별도 내부 인계와 회장님 보고에 남긴다.
7. 시각 자료가 도움이 되면 [비주얼·디자인 담당](../../../agents/visual-designer.md)에게 [stock-visuals](../stock-visuals/SKILL.md)를 적용해 위임한다. 대표/삽화/실데이터 차트를 구분하고 필요한 수량만 정한다. 검증 표가 없는 차트를 가짜 수치로 만들지 않는다. 작가의 배치·alt·캡션과 팩트체커의 수치·축·출처 검수 후 최종 원고에 통합한다. 실제 생성·열람을 맡을 한 명을 정하고 도구 부재 시 계획·대기 상태를 보고한다.

브리프 양식:
- 독자 질문:
- 범위와 기준일:
- 독자·플랫폼·분량:
- 확인할 주장과 필요한 자료:
- 예상 구성:
- 가정 또는 미정 사항:
- 기획 인계 기록: 회의록 URL·회의일·조회일·확정/제안/미정·반영 결정·미해결 사항
- 필요한 시각 자료: 목적·배치·생성/실데이터 구분·근거·담당·검수 상태, 불필요하면 생략

게시 요청이 있으면 목적지와 초안 저장/공개발행 범위, 실제 쓰기 도구·권한을 확인하고 승인된 동작 후 저장 결과를 재조회한다. 이미 승인된 동작은 재승인받지 않는다. WordPress 공개발행 자동화는 설정되지 않았으며 회의록 참고 지시 자체는 현재 발행 요청이 아니다.
WordPress 미디어 자동 업로드도 설정되지 않았다. 이미지 제작과 미디어 업로드·공개발행 완료를 구분하며, 업로드 수행 시 실제 URL·표시·alt를 확인한다.

완료 기준: 기획 조회·반영 여부가 추적 가능하고, 최종 원고의 핵심 주장에 근거가 있으며, 미확인 사항과 실제 저장·발행 상태를 정확히 보고했다.
