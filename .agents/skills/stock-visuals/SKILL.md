# 주식 블로그 비주얼 제작

[프로젝트 지침](../../../AGENTS.md)과 [비주얼·디자인 담당](../../../agents/visual-designer.md)을 따른다. 편집장의 브리프·원고·검증된 근거 표·사용자 참고 이미지를 입력으로 받는다. [Notion 기획 인계](../stock-editorial/references/notion-planning-handoff.md)의 확인된 방향을 재사용하고 제안·미정을 확정하지 않는다. 편집장이 이번 작업에서 조회한 자료를 전달하면 중복 조회하지 않는다.

## 필요한 시각 자료 선택

1. 원고의 독자 질문과 설명이 어려운 부분을 확인하고 이미지의 목적·배치·형식을 정한다. 대표 이미지와 본문 삽화가 필요한지 각각 판단한다. 모든 글에 일정 수의 이미지를 강제하지 않으며 필요 없으면 그 이유를 짧게 전달한다.
2. 대표 이미지에는 [baoyu-cover-image](../../../hr-team/.agents/skills/baoyu-cover-image/SKILL.md), 본문 개념 삽화·설명 도식에는 [baoyu-article-illustrator](../../../hr-team/.agents/skills/baoyu-article-illustrator/SKILL.md)를 직접 읽는다. 실행할 분기의 workflow·prompt·style 참고만 추가로 읽고 원본을 복제하거나 수정하지 않는다. 두 원문의 최상위 version 필드는 현재 OpenAI 형식 검사와 다르므로 자동 발견을 가정하지 않고 이 맞춤 스킬을 진입점으로 사용한다.
3. 실제 금융 수치의 막대·선·워터폴은 검증된 표에서 Python 등 기존 코딩 도구로 그린다. 비교표는 읽기 쉬운 HTML/Markdown 표도 고려한다. 생성 이미지 안의 숫자·주가선·면적을 실제 시장 데이터의 증거로 제시하지 않는다. 개념 삽화는 생성형 설명 그림임을 인계한다.

## 프로젝트 적용 기준

- 외부 원문의 매회 옵션 승인·최초 EXTEND 설정보다 사용자 지시와 이미 승인된 작업 범위를 우선한다. 통상적인 구도·색·비율은 프로젝트 범위에서 합리적으로 정해 알리고 진행한다. 전역 설정·로그인·외부 백엔드를 임의로 설치하지 않는다. 중요한 브랜드·범위 충돌만 편집장을 통해 확인한다.
- 기본은 한국어 독자가 모바일에서 읽기 쉬운 간결한 구성, 최소한의 이미지 내 문구, 워터마크 없음이다. 확정 브랜드가 없으면 색·글꼴은 이번 작업의 제안으로 표시한다. 대표 이미지 비율은 요청과 발행 영역에 맞추며 미지정 시 16:9를 제안값으로 사용한다. 원본의 섹션별 이미지 수·병렬 4개 기본값을 강제하지 않고 필요한 소규모 작업부터 진행한다.
- 현재 세션의 런타임 기본 이미지 도구를 우선 사용한다. image_gen이 노출되어 있으면 실제 이름·입력 스키마로 호출하며 외부 문서의 가상 도구명을 그대로 실행하지 않는다. 사용자가 특정 백엔드를 지정했으면 가용성을 확인한다. 이미지 도구 지침이 생성·편집 방법과 결과 반환 방식을 정한다.
- 생성 전에 전체 최종 프롬프트를 이미지별 prompts/NN-type-slug.md로 저장한다. 승인된 공개 브리프만 사용하고 내부 회의록 원문·개인정보·비공개 내용을 프롬프트·이미지·Git에 복제하지 않는다. 산출물은 작업별 프로젝트 경로에 저장하며 기존 파일은 덮어쓰지 않고 새 버전으로 남긴다. 도구가 반환한 실제 파일/이미지 결과만 기록하고 존재하지 않는 경로를 만들지 않는다.
- 참고 이미지가 로컬 파일이면 편집 전에 실제로 열어 확인한다. 새 생성과 기존 이미지 편집을 구분한다. 기본 이미지 편집은 런타임 이미지 도구를 사용하고 잘못된 한글은 프롬프트를 고쳐 재생성하거나 문구를 줄인다. 명시적인 변환·압축 등 요청이 있을 때만 해당 범위의 다른 도구를 사용하며 코드로 생성 이미지의 글자나 내용을 임의 덧칠하지 않는다. 검증 표로 새 차트를 그리는 작업은 이 이미지 편집과 구분한다.

## 실제 데이터 차트

1. 원데이터 표·공식 출처 URL/문서 위치·기준일·기간·통화·단위·실제/추정 구분을 확인한다. 금융 값은 리서처·팩트체커의 근거를 사용한다. 자료가 없으면 데이터 요구와 차트 설계만 반환하고 임의 수치로 완성본을 만들지 않는다.
2. 데이터 순서·누락·연결/별도·분기/누적을 맞추고 필요한 변환·계산식을 기록한다. 원데이터와 코드로 결과를 재현할 수 있게 한다. 워터폴은 시작값+변동 합계=끝값을, 비교표와 막대는 같은 기준을 검산한다.
3. 축 제목·단위·선형/로그 스케일·범례·기준일·출처를 표시한다. 막대는 기본적으로 0부터 시작하고 범위를 줄이거나 축을 끊으면 명시한다. 결측을 0으로 바꾸거나 선으로 조용히 연결하지 않는다. 이중 축으로 상관관계를 과장하지 않는다. 추정치는 점선 등으로 구분하고 불확실성 구간은 실제 근거가 있을 때만 그린다.
4. 수치를 원고·원자료와 대조하고 계산 및 축의 사실 검수는 팩트체커에게 넘긴다. 색과 모양을 함께 사용하며 한글 폰트 지원·글자 크기·모바일 폭에서 잘림·범례·대비를 확인한다.

## 생성·검수와 도구 대안

1. 이미지 생성 권한·도구가 있는 담당 한 명이 실제 생성과 결과 열람을 맡는다. 디자이너에게 도구가 없으면 프롬프트 파일·계획·배치·검수 기준을 편집장에게 반환하고, 도구가 있는 편집장/상위 실행자가 생성한 결과를 실제로 열어 확인한다. 아무도 생성할 수 없으면 '계획/프롬프트 준비, 생성 대기'로 보고한다.
2. 생성 후 실제 이미지 또는 차트 파일을 열어 원고 의미·오해 소지·한글 오탈자·수치·출처·잘림·모바일 가독성을 확인한다. 프롬프트가 올바르다는 이유만으로 이미지 검수 완료를 주장하지 않는다. 확인할 수 없는 부분은 검수 대기로 남긴다.
3. 실패한 항목만 원인을 반영해 재시도하고 성공한 결과를 중복 생성하지 않는다. 도구가 예상과 다른 출력 경로나 형식을 반환하면 실제 결과를 기준으로 인계한다. 작가는 검수된 파일만 배치하고 팩트체커는 그림·캡션이 주장하는 사실을 함께 검수한다. 편집장이 최종 통합한다.

## 편집장 인계

| 항목 | 기록할 내용 |
|---|---|
| 목적·배치 | 대표/삽화/차트/표, 설명할 논점과 삽입 문단 |
| 파일·결과 | 실제 경로 또는 도구 결과 참조, 파일명·형식·크기/비율 |
| 대체텍스트·캡션 | 핵심 의미를 설명하는 alt, 필요한 생성 삽화 표시·출처·기간·단위 |
| 제작 구분 | 생성형 삽화 / 검증된 실제 데이터 차트 / 예시 도식 |
| 재현·근거 | 프롬프트 경로 또는 원데이터·코드, 출처·기준일·변환식 |
| 상태 | 계획/생성됨/시각 검수/사실 검수/수정 대기, 미해결 사항 |

WordPress 미디어 자동 업로드·발행은 설정되지 않았다. 역할 구성이나 이미지 제작 승인은 현재 업로드 요청이 아니다. 실제 게시 요청에서는 승인된 목적지·범위와 쓰기 권한을 따르고 이미 승인된 동작을 재승인받지 않는다. 업로드를 수행했다면 실제 미디어 URL·표시·alt를 확인하고 로컬 생성과 업로드·공개발행 상태를 구분한다.

완료 기준: 필요한 시각 자료 또는 명확한 대기 계획이 있고, 실제 제작·검수 상태와 근거·배치·alt·캡션을 편집장에게 전달했다. 파일 구성만으로 실제 이미지 생성이나 상시 실행을 주장하지 않는다.
