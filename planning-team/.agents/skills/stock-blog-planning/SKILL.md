# 주식 블로그 인터뷰와 기획서

[프로젝트 지침](../../../../AGENTS.md), [기획팀장](../../../agents/planning-lead.md), [기획서 담당](../../../agents/planning-writer.md)의 역할을 따른다. 인터뷰에는 [질문 가이드](references/interview-guide.md), 작성에는 [기획서 양식](references/planning-brief-template.md)을 읽는다.

## 원문 스킬과 기존 기능 재사용

- 질문의 의존성과 빠진 가정은 [grilling](../../../../hr-team/.agents/skills/grilling/SKILL.md)으로 점검한다. 한 번에 전체 질문을 나열하는 대신 사용자의 한 번에 1~2개 질문 선호를 우선한다.
- 콘텐츠 방향은 [content-strategy](../../../../hr-team/.agents/skills/content-strategy/SKILL.md)를 적용한다. B2B 구매 전환·고정 비율·예시 수치는 우리 사실로 사용하지 않는다. 목적은 사용자와 합의한 독자 교육·구독·신뢰 등으로 바꿔 해석한다.
- 글별 브리프는 [stock-editorial](../../../../.agents/skills/stock-editorial/SKILL.md), 자료 조사와 근거 검수는 [stock-research](../../../../.agents/skills/stock-research/SKILL.md)와 [stock-fact-check](../../../../.agents/skills/stock-fact-check/SKILL.md)를 재사용한다. 내용을 복제한 새 스킬을 만들지 않는다.
- 금융 질문 프레임이 필요할 때만 [실적 전망 참고](../../../references/financial/earnings-preview.md)와 [산업 개요 참고](../../../references/financial/sector-overview.md)를 읽는다. 이 파일은 질문 프레임용 참고자료이며 실행 스킬이나 최신 금융 데이터가 아니다.

## 인터뷰 진행

1. 현재 대화와 알려진 자료에서 이미 답한 내용·확정 사항·조사할 사실을 먼저 정리한다. 에이전트가 확인 가능한 사실을 회장님에게 대신 조사해 달라고 묻지 않는다.
2. 목표와 독자처럼 뒤의 선택을 바꾸는 선결 질문부터 한 번에 1~2개만 묻는다. 답을 받은 뒤 다음 질문을 정한다. 회장님 선호·판단은 회장님에게 확인하고, 시장·플랫폼·기업 관련 사실은 접근 가능한 근거로 조사한다.
3. 질문 UI와 사용자 질문은 기획팀장만 담당한다. 기획서 담당 등 자식 에이전트는 빠진 항목과 질문 초안을 팀장에게 반환한다.
4. 핵심 목표·독자·시장·포맷·자료 근거 계획·운영 여력·성공 기준이 기획 가능한 수준이면 종료한다. 완벽한 답을 얻으려고 질문을 계속하지 않는다. 비핵심 미정은 제안과 함께 남긴다.
5. 인터뷰 결과를 확정·제안·미정으로 나눠 짧게 요약하고 확인한다. 이미 확인된 답을 재질문하지 않는다. 사용자가 가정에 기반한 초안을 요청하면 그 범위에서 가정을 명시해 진행한다.

## 기획서 제작과 검토

1. 확인된 인터뷰 결과를 기획서 담당에게 실제 서브 에이전트 도구로 위임한다. 역할·스킬 경로, 목표, 근거, 산출물, 완료 조건과 수정 범위를 전달한다. 인터뷰 중 전문 담당의 독립적인 자료 조사는 가능하지만 미정 선호를 확정한 기획서로 만들지 않는다.
2. 블로그 방향과 차별점, 적정 수의 주제축, 연재 주제, 글별 자료·반론·갱신 기준, 운영 계획·성공 기준, 편집장 인계를 작성한다. 요구가 바뀌면 영향받는 부분만 갱신한다.
3. 팀장은 회장님의 답, 사실 근거, 운영 여력, 품질 기준과 결과를 대조하고 기획 검토를 받는다. 기획팀 생성 승인과 개별 기획의 최종 승인을 구분한다. 이미 승인된 내용은 재승인을 반복 요구하지 않는다.
4. 승인된 방향은 편집장이 글별 브리프·집필·검수를 진행할 수 있는 형태로 인계한다. 결정 기록이나 Notion 저장은 [비서실](../../../../executive-office/README.md)의 기존 흐름을 재사용한다.
5. 간단한 수정은 팀장이 직접 처리할 수 있다. 서브 에이전트 도구가 없으면 역할별로 처리하고 실제 위임하지 않았음을 알린다.

## 주식 분석 범위와 실행 조건

- 사실·해석·전망을 구분하고 출처·기준일·단위·통화를 명시한다. 성공 기준은 측정 방법과 검토 시점을 합의하며 수익이나 검색 순위를 보장하지 않는다.
- 차트 요청은 이미지 해석, 가격·거래량 시계열, 지표 계산, 전략 백테스트 중 무엇이 필요한지 구분한다. 전문 스킬·원자료·실행 도구·검증 조건을 확인하기 전 분석 역량이나 데이터 연결을 완료했다고 주장하지 않는다.
- 새 라이브 데이터·금융 API·Notion 연결을 자동 설치하지 않는다. 필요한 조건은 미정·대기 사항으로 기록하고 가능한 기획 작업을 계속한다.
- 개발 요구는 콘텐츠 기획과 분리해 범위·입출력·인수 기준만 정리한다. 별도 실행 요청 없이 개발·배포·GitHub 이슈 게시·외부 발행을 하지 않는다.

완료 기준: 핵심 요구와 근거가 기획안에 반영되고 확정·제안·미정 및 승인 상태가 구분되며, 편집장이 이어받을 자료와 남은 조건이 준비되어 있다.
