# 작업 분기와 인수 기준

필요한 행만 사용한다. 프로젝트 환경이 미확인일 때 실제 구현이나 측정 결과를 지어내지 않는다.

| 분기 | 먼저 확인 | 담당·결과 | 검증 예시 |
|---|---|---|---|
| WordPress.com | 요금제·사용자 역할·허용된 테마/플러그인·개발 접근 | 팀장이 가능한 작업 범위를 정함 | 실제 권한과 지원 기능 대조 |
| 자체 호스팅 | 저장소·배포 방식·스테이징·PHP/WP 버전·백업 | 개발 담당이 환경에 맞는 변경 | 기존 빌드·테스트와 스테이징 확인 |
| 블록 테마/편집기 | theme.json·템플릿·패턴·등록 블록·빌드 체계 | 개발 담당 구현, UI 담당 설계 검수 | 편집 화면과 프런트 출력 모두 확인 |
| 클래식 테마 | PHP 템플릿·훅·자식 테마·CSS | 기존 확장 지점을 활용 | 템플릿 회귀·동적 출력 검수 |
| 페이지 빌더 | 빌더 종류·버전·템플릿 저장 위치·편집 권한 | 빌더 방식의 설계/구현 | 에디터와 실제 페이지·반응형 확인 |
| 구조·성능·로그 | 실제 URL/코드·측정 도구·기간·수집 권한 | 분석 담당의 근거 있는 문제 목록 | 전후 동일 조건·원인 후보와 확정 구분 |
| SEO | 렌더 HTML·robots·canonical·sitemap·리다이렉트·SEO 플러그인, 선택 GSC/GA4 | SEO 담당의 수정 명세·영향 | 메타 중복·HTTP·크롤링 설정·내부 링크, 연결 시 실제 검색 데이터 |
| 디자인 추가 확인 | 기존 대화·확정 기획·코드로 해결되지 않는 중요한 사용자 선택 | UI 질문 초안 → 팀장 질문 1~2개 → 확정/제안/미정 브리프 | 의존 질문 순서·기존 답 재사용·필수 답 대기·위임 선택 인터뷰 생략 |
| UI·접근성 | 목표 독자·주요 화면·브랜드·장치·사용 흐름 | UI 담당 설계, 개발 담당 구현 | 모바일/데스크톱·키보드·초점·라벨·대비·확대·레이아웃 이동 |
| 운영 적용 | 정확한 대상·기존 승인·백업/복구·적용 순서 | 단일 작성자의 적용과 복구 계획 | 실제 적용 결과·핵심 기능·오류·복구 가능 상태 |

검수 기록: 대상/버전, 확인 시각(Asia/Seoul), 도구와 조건, 관찰 근거, 변경안, 적용 여부, 테스트 결과, 미확인 사항, 다음 담당. 기존 승인과 목적지가 분명하면 반복 질문하지 않는다.
